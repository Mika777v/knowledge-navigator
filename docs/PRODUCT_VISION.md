# PRODUCT VISION — 社内規程ナビ（Knowledge Navigator）

> ステータス: Draft v0.1 / 2026-10-20
> 本プロダクトで扱う文書・組織・人物はすべて架空のダミーデータ（架空企業「架空商事株式会社」）です。

---

## 1. ビジョンステートメント

> **「何を調べればいいかわからない」を、「誰に・何を・どこで」まで案内する。**

社員は制度名も文書名も知らなくてよい。
「結婚した」「子どもが生まれる」「引っ越す」といった **自分の状況** を言葉にするだけで、
**使える制度 → 根拠となる規程の該当箇所 → 申請方法 → 問い合わせ先** までたどり着ける。

社内規程ナビは「検索エンジン」ではなく **ナビゲーションシステム** である。

---

## 2. 解決する課題

| # | 利用者の課題 | 現状で起きていること | 本プロダクトでの解決 |
|---|---|---|---|
| P1 | どの文書を見ればよいかわからない | 共有フォルダのPDFを片端から開く | 状況→制度→文書への逆引き |
| P2 | 制度名がわからない | 「結婚祝金」という単語を知らないので検索できない | ライフイベント・類義語辞書・FAQによる言い換え吸収 |
| P3 | 問い合わせ先・担当部署がわからない | 総務に聞いたら人事と言われ、たらい回し | 制度・文書ごとに担当窓口を構造化データとして保持し必ず提示 |
| P4 | 何を検索すればよいかわからない | 検索窓の前で手が止まる | 「きっかけ（ライフイベント）」から辿る導線、よくある質問の提示 |
| P5 | （管理側）同じ問い合わせが繰り返し来る | 人事・総務の工数を圧迫 | 検索ログ・ゼロヒットクエリの可視化 → FAQ改善サイクル |

## 3. ターゲットユーザーとペルソナ

| ペルソナ | 属性 | 主なジョブ | 成功の定義 |
|---|---|---|---|
| **佐藤（一般社員・入社3年目）** | 結婚を控えている | 使える制度と申請方法を知りたい | 3分以内に「結婚祝金・結婚休暇・人事部へ申請」が分かる |
| **鈴木（新入社員）** | 入社1か月 | 通勤手当・在宅勤務・PC貸与のルールを知りたい | 制度名を知らなくてもたどり着ける |
| **田中（管理職）** | 部下8名 | 部下の育休・介護休業の手続き確認 | 管理職向け手順と人事窓口がすぐ分かる |
| **高橋（人事担当）** | 規程管理者 | 規程・FAQの更新、問い合わせ削減 | 改定が即日反映、ゼロヒット語からFAQを追加できる |
| **伊藤（総務担当）** | 慶弔・備品担当 | 慶弔見舞金・社内ルールの周知 | 担当業務の問い合わせが減る |
| **渡辺（情報システム担当）** | システム管理者 | ユーザー・権限・監査・運用 | 権限誤設定による情報漏えいがゼロ |

## 4. プロダクト原則

1. **Navigation over Search** — 検索結果は「文書の一覧」ではなく「制度・文書・該当箇所・窓口」を構造化して返す。
2. **Contact is always shown** — どんな検索結果にも（ゼロヒットでも）「次に誰に聞けばよいか」を必ず表示する。
3. **Grounded by default** — AI回答は必ず根拠文書・参照箇所を伴う。根拠がなければ回答しない。
4. **Structured first, AI second** — 制度・窓口・関係性は構造化データで持ち、AIは「言い換え吸収」と「要約」に限定して使う。AIなしでも価値が出る。
5. **Permission before relevance** — 権限フィルタは関連度計算より先に適用する（見えてはいけないものは候補にすら入れない）。
6. **Measure search quality** — 検索品質を「評価用質問セット」で継続計測し、改善を数値で語る。

---

## 5. 提供価値（Value Proposition）

- **社員**: 調べる時間の短縮、制度の取りこぼし防止（もらえるはずの祝金を申請し忘れない）
- **人事・総務**: 定型問い合わせの削減、規程の最新版を単一ソースで管理
- **情シス**: 共有フォルダ散在の解消、アクセス制御・監査の一元化
- **経営**: 制度利用率の向上（福利厚生の投資対効果向上）

---

## 6. 成功指標（North Star / KPI）

| 種別 | 指標 | 目標（PoC想定） |
|---|---|---|
| **North Star** | 検索セッションのうち「窓口または該当箇所に到達」した割合（Navigation Success Rate） | 70%以上 |
| 品質 | 評価用質問セットでの Hit@5（正解制度/文書が上位5件に含まれる） | Phase1: 70% → Phase3: 85% → Phase5: 90% |
| 品質 | ゼロヒット率 | 10%未満 |
| 効率 | 1セッションあたりの到達時間（中央値） | 60秒以内 |
| 満足度 | 「役に立った」率（結果画面のフィードバック） | 75%以上 |
| 運用 | ゼロヒット語 → FAQ/類義語追加までのリードタイム | 1週間以内 |

> ポートフォリオ上は、ダミーの「評価用質問セット（100問）」で品質指標をCIで計測し、フェーズごとの改善をグラフで示す。

---

## 7. スコープ外（Non-Goals）

- 人事システム・勤怠システムへの申請代行（申請先の **案内** までが責務）
- 個人の給与・評価など個人データの照会
- 汎用チャットボット（規程・社内ナレッジ外の雑談には答えない）
- 規程の法的解釈の保証（最終判断は担当部署へ誘導する）

---

## 8. 将来像

```
Phase1-3: 構造化ナビゲーション（制度・文書・窓口・FAQ・辞書）  ← AIなしで成立
Phase4  : 意味検索（言い換えに強くなる）
Phase5  : RAG（根拠付き回答文の生成）
Phase6  : AIアシスタント（状況ヒアリング → 該当制度の網羅提示 → 申請チェックリスト）
将来    : Teams/Slack連携、人事システム連携、多言語（外国籍社員向け）
```
